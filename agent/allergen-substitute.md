# 过敏原与替餐（§5–§6）

> 本文件是 [AGENTS.md](../AGENTS.md) 的明细（§5–§6），只在做对应任务时读。

## 5. 过敏原标记

这是识别后的**确定性步骤**，不要让视觉模型自由发挥。

### 5.1 输入

- `public/assets/data/allergens.json` 中的 `id`、`name`、`keywords`。
- 菜品名称 + 食材名称。
- 人工维护的别名/反例表（建议放 `agent/allergen_aliases.json`）。

### 5.2 匹配规则

1. 将菜名与每个食材名做去空白、去标点后的匹配。
2. 对每个过敏原使用长词优先：`酸牛奶` 先于 `牛奶`，`蛋黄酱` 先于 `蛋黄`。
3. 只输出 `allergens.json` 中存在的 id。
4. 命中即标记；存在歧义时同时标记并写入 `UNKNOWN_ALLERGEN` 或低置信警告，交人工确认。
5. 不要使用单个泛化字 `奶` 做匹配，否则会把 `奶白菜` 误判为牛奶。不要用 `牛` 匹配牛奶，否则会把牛肉误判。
6. 不要根据菜名类别凭空推断隐藏配料；但可以使用已审核的别名表。例如 `蛋糕` 默认含蛋，需在别名表中明确配置后才标记。

建议的扩展别名（维护在 Agent 侧，避免改动前端）：

```text
egg: 鸡蛋, 蛋, 蛋黄, 蛋清, 蛋羹, 蒸蛋, 鹌鹑蛋, 皮蛋, 蛋花, 蛋黄酱, 蛋糕, 蛋挞, 蛋面
milk: 牛奶, 鲜奶, 纯牛奶, 酸牛奶, 酸奶, 奶粉, 奶油, 芝士, 奶酪, 淡奶, 奶香, 奶黄, 炼乳
```

明确排除：`米奶`、`豆奶`、`椰奶`、`燕麦奶`、`杏仁奶`、`奶白菜`。

猫、坚果等不在当前过敏原词库中的项目，不得自行写入 `riskAllergens`。

### 5.3 输出

```json
"riskAllergens": ["egg", "milk"]
```

前端只读取这个数组，不会根据食材重新判断。因此 Agent 的这一步是安全关键路径，必须可重复、可测试。

## 6. 替餐匹配

### 6.1 优先级

1. 人工确认过的菜品专属替餐 → `dish.substitute`
2. 动态替餐库 `substitute-library.json`
3. 旧版 `substitutes.json` 全局映射，仅作回退
4. 都没有 → `null`，前端显示“暂无推荐替餐”

动态替餐库结构：

```json
{
  "recipes": [
    {
      "id": "sub-egg-steamed-tofu-pork",
      "name": "肉末蒸豆腐",
      "replaces": ["egg"],
      "ingredients": ["嫩豆腐", "瘦肉末", "小葱"],
      "usedFor": ["肉沫蒸滑蛋", "蒸蛋羹", "肉沫蒸水蛋"],
      "tags": ["蛋白质", "钙", "软食"],
      "verified": true,
      "priority": 100
    }
  ]
}
```

选择逻辑：

- 候选必须覆盖该菜品命中的**全部**过敏原；
- 营养结构优先：原菜含肉/蛋/豆、蔬菜、主食（或水果）时，候选的 `tags` 必须覆盖对应营养组（`蛋白质`/`蔬菜`/`主食`/`水果`），例如「三丝炒米粉」要求同时有主食、蛋白质、蔬菜，纯红薯/发糕这类只有主食的候选会被排除；
- 在满足营养组的候选里，优先 `usedFor` 精确命中菜名；
- 再看 `verified`、`priority`；
- 营养组或品类/餐次没有候选时逐级放宽（依次丢掉品类、营养组、餐次），保证有回退结果；
- 同一餐内不重复使用同一个替餐候选；
- 整餐搭配：本餐已有汤水（汤/粥/汤面）时，替餐再上汤水会被大幅降权，避免「两样都是稀的」；本餐已有同类蛋白（如汤里有瘦肉）时，另一份同类蛋白也会降权；连两天同一餐次用同一个替餐按 3000 分降权，隔天再用降 600 分（可用但排后）；
- 无候选才回退旧版全局表。

替餐落地后会再跑一遍**整餐审核**（`auditMeal`，结果在 `MenuMeal.audit`，页面上是「搭配审核」小块、周表「当天小结」里的「搭配提醒 N」），只查结构不查数值：

| 检查 | 触发条件 |
| --- | --- |
| 没主食 | 正餐里没有任何主食 |
| 两样稀的 | 一餐至少两道汤/粥/汤面 |
| 两样干的 | 早餐两道都是干主食、没有粥汤 |
| 蛋白重复 | 至少两道菜同一蛋白来源（猪/鸡/牛/鱼虾/蛋/豆制品/鸭），且其中至少一道是替餐（原菜单自带的重复不归替餐管） |
| 缺蔬菜 / 缺蛋白 | 午餐、晚餐没有蔬菜或没有蛋白质 |

点心餐（早点/午点）只给水果小食，不做正餐标准审核。

### 6.2 打印与营养

- 前端页面会展示动态替餐库候选及标签。
- DOCX 和浏览器打印只显示已确认的菜品专属替餐，不会把未确认推荐打印成确定方案。
- `tags` 用于看护人判断营养结构（蛋白质/钙/主食/蔬菜等），不伪造热量或营养素数值。
- 匹配只做「营养组有无」的结构对齐（避免主食换主食、蛋白换主食），不做热量/克重换算；要精确到数值必须接入有来源的营养成分表。
- 新增替餐条目时必须写 `tags`，至少覆盖 `主食`/`蛋白质`/`蔬菜`/`水果` 中适用的项，否则会因营养过滤被降级、排到后面。
- 新增替餐条目时必须写 `method`（做法）：替餐是家长在家做好带到幼儿园，做法要写成能直接照做的短句（配比、火候、能提前备的步骤、复热方式）。页面在替餐建议和溯源弹窗里显示「在家做法」，菜品专属替餐若与库里同名（如「米奶」）也复用库里的做法。
- 替餐库可以放心扩充：不依赖幼儿园后厨，新增菜只要保证不含目标过敏原、适合 3–6 岁、能带饭复热即可。目前库里 32 条，覆盖蛋/奶两类，正餐补了鱼虾、牛肉、鸡肉、豆制品与蔬菜搭配。
- 早餐条目要**简单好做**：优先蒸、煮、煎饼这类一到两步、能前一晚备好或冷冻复热的（蒸山药、蒸玉米、豆沙包、香蕉松饼、小米南瓜粥）；不要放需要现炒多道工序或造型菜。正餐才用带菜带肉的组合（清蒸鲈鱼、包菜虾肉丸、番茄土豆炖牛肉、香菇滑鸡、西兰花炒虾仁）。
- 若要实现数值化营养均衡，必须接入有来源的营养成分表，再给候选补充 `nutrition` 字段；当前版本不写假数据。

### 6.3 规则

- 不要用视觉模型临时编造替餐。
- 如果原文档有确认过的括号替餐（如 `纯牛奶（米奶）`），先放入复核项；人工确认后再写 `dish.substitute` 或加入替餐库。
- 同一菜品含两种过敏原时，替餐库候选必须 `replaces` 同时包含两个 id；否则保持未确认。
- `verified: true` 的替餐条目不允许自动修改。
- 牛奶类饮品（`牛奶`、`纯牛奶`、`酸牛奶`）的替餐统一为 `米奶`，直接写入 `dish.substitute`，不交给动态库按用量轮换（否则同一周会出现无糖豆浆/燕麦奶/椰奶）。含奶的固态点心（如 `奶香馒头`、`奶香小馒头`）仍按替餐库匹配主食类替餐。
